# תשתית תיעוד, סקילים, אבטחה ובדיקות

## היקף ואופן עבודה

יישום התוכנית שאושרה בצ׳אט: משימות עוקבות, ללא עיצוב מחדש, מיגרציית Auth או שינוי מוצר אגבי. כל משימה כוללת אימות ועדכון סטטוס לפני המשימה הבאה. מקור האמת המתוחזק הוא `docs/specs`; התיעוד יתאר את המימוש הקיים ולא יעדים עתידיים כאילו הושלמו.

## מניעת ביטול בקשת session בסגירת חלון ההתחברות — 2026-11-04

שוחזרה סגירת חלון `/auth/callback` כשבקשת ה־session שלו עדיין ממתינה. המתנה לסטטוס של SessionProvider בלבד עדיין השאירה בקשה נוספת בפיתוח, והבדיקה זיהתה `CLIENT_FETCH_ERROR`. חלון החזרה מבצע כעת בקשת `getSession()` אחת מפורשת ומשתמש באותו Promise בחיבור חוזר של האפקט. רק במסלול זה ה־provider מתחיל ללא session; יתר המסלולים ממשיכים לטעון session כרגיל. החלון ממתין לסיום הבקשה, מודיע לחלון האב ונסגר, או טוען מחדש את דף הבית כשאין חלון אב. ההודעה מבקשת רענון ואינה מאמתת משתמש בפני עצמה. בוטלו בדיקת זהות נוספת והפניה לעמוד שגיאה שנוספו מעבר לתיקון, וכן ההגדרה הנוספת לרענון במיקוד והשימוש ב־router. הבדיקות מחליפות Google רק בקוד הבדיקות ומשתמשות ב־session חתום מקומי; לא נוסף מעקף אימות באפליקציה.

בדיקת בקשה מעוכבת נכשלה לפני התיקון. לאחר הצמצום עברו שש בדיקות Chromium במחשב ובמובייל: בקשה מעוכבת ללא שגיאת fetch, הודעת חזרה ללא session שאינה מחברת אורח, וחזרה ללא חלון אב. הן הורצו עם `TEST_UI=1` מול שרתי הפיתוח המבודדים הקיימים. `bun run check` עבר עם 57 בדיקות יחידה, טיפוסים וקישורים ב־22 מסמכים פעילים; lint ללא שגיאות ועם חמש אזהרות קיימות. `git diff --check` עבר. לא בוצעו build שחרור, Google OAuth אמיתי או פריסה; אימות Google ופופאפ אמיתיים נותר ידני.

## פישוט לעבודה עצמאית — 2026-11-03

הושלם מקומית, לפי אישור המשתמשת: בדיקת הסיום הכפולה של הסוכן והבדיקה הייעודית שלה הוסרו; מדריך השינוי אוחד ב־README וב־AGENTS והסבר ה־CI במדריך הבדיקות; אינדקס ההיסטוריה צומצם לקישור לארכיון; ענף ו־PR הם בחירה לפי גודל השינוי; ו־CI מוגדר לפעול גם בדחיפה ל־main. Husky, בדיקות האתר, בדיקות האבטחה והארכיון נשארים.

`bun run check` עבר: lint ללא שגיאות (8 אזהרות קיימות), TypeScript, קישורים ב־22 מסמכים פעילים ו־33 בדיקות יחידה. YAML, טריגרים ל־main/PR/הרצה ידנית, הרשאות ופקודות בדיקות הדפדפן אומתו מקומית; לא נותרו הפניות פעילות לקבצים שהוסרו. בדיקות דפדפן לא הורצו מחדש בשינוי תיעוד וכלים זה. לא בוצעו commit, push או שינוי הגדרות חשבון; הרצת GitHub בפועל ממתינה להעלאה.

## החלת תיקון הבקאנד — 2026-11-04

לפי בקשת המשתמשת והרשאת הכתיבה שאושרה, התיקון הוחל ב־`life-questions-server` אחרי אימות שהקבצים לא השתנו מאז הכנתו. סכמות הרשמה ועדכון פרופיל מחייבות `marketingConsent: true` מפורש. עודכנו Swagger ובקשות בדיקות האינטגרציה הקיימות, נוספו בדיקות חוזה עם Prisma מדומה והוסרה הדפסת payload מתשובות הצלחה. לא בוצעה מיגרציה, הסכמות משתמשים קיימים לא שונו ולא בוצעו commit, push או פריסה.

בדיקת TypeScript של מקור הבקאנד ו־`git diff --check` עברו. 12 בדיקות חוזה עברו בתצורה מבודדת מול קובצי הבקאנד שהוחלו, ללא הכנת מסד; נבדקה גם יצירת Swagger בפועל וששתי סכמות הבקשה מסמנות הסכמה כשדה חובה עם הערך היחיד true. הרצת Jest הרגילה נעצרה לפני הבדיקות בקובץ `tests/setup.ts`, עקב TS2304 על `afterAll`; תצורת ההרצה המבודדת אינה מפעילה את הכנת המסד המשותפת. בדיקת קישורי 22 המסמכים הפעילים עברה. בדיקות אינטגרציה מול מסד וזרימות בשירות הפרוס לא הורצו. הרשומות מ־2026-11-03 להלן מתארות את המצב לפני מתן הרשאת הכתיבה והחלת התיקון.

## הסכמה חובה לשיווק — 2026-11-03

לפי הבהרת המשתמשת, נדרש אישור לקבלת שיווק בהרשמה וגם בכל שמירת פרופיל. הטפסים וסכמות שרת Next דורשים boolean true מפורש; תיבת ההרשמה מתחילה לא מסומנת, הנוסח מציין תוכן שיווקי במייל וחובה, ושגיאת הפרופיל מקושרת לתיבה גם לקוראי מסך. פרופילים קיימים ללא הסכמה נשארים קריאים ונדרשים לאשר לפני שמירה; אין הסכמה אוטומטית או שינוי גורף בנתונים קיימים.

ה־patch המקומי לבקאנד עודכן לחייב `marketingConsent: true` בהרשמה וב־PATCH, ללא default בהרשמה. נכללו Swagger, התאמת בקשות בדיקות האינטגרציה הקיימות לחוזה ותוספת בדיקות מבודדות ליצירה/עדכון ולדחיית false, שדה חסר, null ומחרוזת לפני גישה למסד. הבקאנד עצמו נותר ללא שינוי, בהתאם להרשאת הכתיבה שלא אושרה; התיקון דורש החלה ופריסה בנפרד. אין צורך במיגרציית מסד לשינוי הולידציה הזה.

אימות: `bun run check` עבר עם 57 בדיקות יחידה, טיפוסים וקישורים ב־22 מסמכים; lint ללא שגיאות ועם שש אזהרות קיימות. `bun run test:e2e` עבר עם 68 בדיקות Chromium למחשב ולמובייל מול build מבודד, כולל חסימת הרשמה/שמירה ללא הסכמה, אישור במקלדת, נגישות ושתי ערכות נושא. צילומי פרופיל במחשב בהיר ובמובייל כהה נבדקו חזותית. 12 בדיקות חוזה בקאנד עם Prisma מדומה ו־TypeScript של מקור הבקאנד המתוקן עברו. `git apply --check` ל־patch מול ריפו הבקאנד ו־`git diff --check` עברו. בדיקות אינטגרציה של הבקאנד מול מסד וזרימות Google או מוטציות אמיתיות לא הורצו.

## בדיקת הקישור לבקאנד — 2026-11-03

היקף העבודה לפי בקשת המשתמשת: מיפוי מסלולי הקריאה/כתיבה והשוואת החוזה גם לריפו `life-questions-server` המקומי. התיקונים המתוכננים הם יישור ולידציית טפסים בשרת Next, תיקון עימוד ה־sitemap למגבלת 50 של Core API, טיפול בתשובות HTTP/envelope לא תקינות ובדיקת זהות המשתמש המוחזר ממוטציות. בבקאנד נדרש לכלול `marketingConsent` בעדכון פרופיל ולהסיר הדפסה של payload מלא ללוג. תיקון איפוס מוסד בפרופיל ישלח null בהתאם לחוזה PATCH הקיים. אין שינוי במדיניות ההתחברות, הגישה לסיפורים או מנגנון המטמון.

הושלמו תיקוני הפרונט: סכמות הקלט נגזרות מכללי הטפסים; עימוד החיפוש נבדק לפני יציאה לבקאנד; ה־sitemap אוסף עמודים של 50 ומסיר כפילויות; מוסד ריק בפרופיל נשלח כ־null; תשובות משתמש ממוטציות מאומתות גם מול זהות ה־session. לקוח השרת מזהה מעטפת לא תקינה ותקלות JSON/רשת בלי להפוך תשובת 404 לא תקינה למשתמש חדש. דוגמת הסביבה עודכנה לפורט הבקאנד המקומי 3001.

אימות הפרונט עבר: `bun run check` עם 53 בדיקות, TypeScript וקישורים ב־22 מסמכים פעילים, ללא שגיאות lint ועם שש אזהרות קיימות; `bun run test:e2e` עם 68 בדיקות Chromium למחשב ולמובייל מול build מבודד; `git diff --check`. שבע קריאות GET לשירות המוגדר חזרו עם HTTP 200 ועברו ולידציית הסכמות: ארבע רשימות עזר, featured, weekly והמלצות. לא נשלחו מוטציות או מיילים לשירות האמיתי ולא נבדק Google OAuth אמיתי.

תיקון הבקאנד הוכן בעותק זמני עם ארבע בדיקות Jest המשתמשות ב־Prisma מדומה, וכולן עברו. בדיקת TypeScript של קוד השרת בעותק עברה. הבדיקות הורצו באמצעות סקריפט Bun, בתוך הסביבה המוגבלת ובלי Watchman; ניסיון הרצה ישירה של Jest באמצעות runtime של Bun לא תאם לכלי. בדיקות הבקאנד המחוברות למסד נתונים לא הורצו.

הרשאת הכתיבה לריפו האח לא אושרה, ולכן `life-questions-server` נותר ללא שינוי. נשמר patch מקומי ב־`.cache/quality/backend-connectivity.patch` עם שינוי הסכמה, Swagger, הסרת הדפסת payload ותוספת הבדיקות. `git apply --check` מול ריפו הבקאנד עבר. הסכמה לעדכונים והסרת payload מהלוג עדיין דורשות החלה ופריסה של התיקון בבקאנד; שום שירות לא נפרס במסגרת העבודה.

## פירוט התוצרים שהושלמו

מפרט UI מפריד RTL, מקלדת, נגישות, רספונסיביות ושימוש חוזר מבחירות מראה משתנות. CSS/config וממשקי הרכיבים הם מקור ערכי העיצוב. אין טבלאות צבעים/מידות מקבילות שנדרש לתחזק ידנית.

### 5: סקילים

נשמרו שני סקילי Vercel ברמת המשתמש, והותקנו frontend-design, security-best-practices ו־playwright-cli לאחר סקירת המקור. לפי בקשת המשתמשת בוטלו רישום מקורות הסקילים בקובץ נפרד ובדיקת המבנה שלו; מדריך הבדיקות עודכן בהתאם. הסקילים עצמם נשארים מותקנים.

בפרויקט נשאר רק life-questions-ui. הוא מכוון לקריאת מפרטים ורכיבים, טוקנים, שמירת התנהגות ובדיקת דפדפן. אינו מוסיף ספריות, קאש או שפת עיצוב מעצמו. validator הרשמי וקישורים מקומיים עברו; נבדק שמסלול ההנחיות מתאים לשינוי צבע, פריסה ומובייל.

### 6–9: איכות ואבטחה

ESLint הוחזר לגרסה תואמת עם Next, הוחרגו פלטים אוטומטיים וקוד דוגמה, ותוקנו שגיאות קוד פעילות בלי לכבות כללים. בדיקה שלילית הוכיחה שהכללים עדיין מזהים שגיאה. נשארו שמונה אזהרות גלִויות המתועדות ב־backlog.

בוצעו עדכוני אבטחה סלקטיביים בתלויות הישירות והעקיפות. התקנה frozen עברה לאחר הוספת כל הכלים. אין High/Critical; minimatch moderate נשאר גלוי עם החלטה מתועדת. Bun המקומי וב־CI מקובע ל־1.3.12. NextAuth נשאר v4.

בדיקות Bun נפרדות מאיסוף Playwright. קיימים fixtures קטנים בדויים, בדיקות סכמות, תוצאות/עימוד/ביטול בקשות, SSR והידרציה, הרשאות ו־session. נוספה רגרסיה גם לכשל מאוחר של בקשה שבוטלה.

עדכון session מתעלם מהלקוח ומרענן משתמש לפי Google subject מהימן. תשובת השרת מאומתת, ורק 404 נחשב משתמש חדש. legacy cookies דורשים כניסה מחדש. בדיקות הראו ניסיונות להחליף id/googleId/סטטוס הרשמה שנכשלו לפני התיקון ועברו אחריו. פעולות profile, פנייה לסיפור ו־BFF search מאמתות הרשאה עצמאית; חיפוש פנימי ל־sitemap נשאר זמין ללא session דפדפן. לא נוצרה תלות מעגלית בקוד session.

### 10–12: בדיקות דפדפן

הסביבה מפעילה API מדומה ב־4100 ו־Next ב־3100 עם build ב־.next-e2e. היא דורסת ערכי סביבה מהימנים בערכי בדיקה, מספקת נתונים גם ל־RSC ול־Server Actions ומייצרת sessions חתומים בקוד בדיקה בלבד. אין נתיב אימות עוקף באפליקציה. מצבי הצלחה, ריק, שגיאה, תשובה פגומה והשהיה ניתנים לשחזור. הנתונים מתאפסים בכל בדיקה והריצה טורית.

שלוש בדיקות ההיכרות מכסות בית, פתיחת דוגמה וקלט שגוי ביצירת קשר. הן הורצו גם ב־UI ונצפו הצעדים. כישלון אמיתי במהלך פיתוח הבדיקות הפיק צילום ו־trace. הורחב הכיסוי לאורח, כניסה, URL, קטגוריות, עימוד, מרוץ בקשות, שגיאות, ניווט בין סיפורים, סיפור חסר, יצירת קשר, פרופיל והשלמת הרשמה. גם כשלי שמירה/הרשמה שומרים את הטיוטה. אין בדיקת דירוג של מנוע החיפוש החיצוני.

הבדיקות חשפו ותיקנו שימוש בטיוטת מסננים בעימוד, שגיאת חיפוש שלא הוצגה וכשל מיושן שהשפיע על state חדש. בדיקות הדפדפן נכשלות גם על חריגת runtime או הודעת הידרציה.

### 13: נגישות ו־UI

FormField מקשר Label ושגיאה ל־Input/textarea ישירים עם useId, aria-describedby ו־aria-invalid, תוך שמירת ref ומזהה מפורש. תוכן קריאה בלבד מקבל caption. מזהי הסכמה נפרדים בין טפסים. רכיבי בחירה מקבלים שם/מצב נגיש, וכרטיס סיפור הוא Link. חלון הכניסה שומר focus ומחזירו לסוגר.

axe ומקלדת נבדקים בתוכן הראשי ובחלון ההרשמה. צילומים נשמרים לעיון במחשב ובמובייל ובשתי ערכות הנושא; אין baseline פיקסלים מחייב. תוקנו ניגודיות מוכחת, loading משותף ושגיאת הידרציה בתנועה מופחתת. התנועה המופחתת מיושמת ב־CSS כך ש־SSR והלקוח מתחילים באותן תכונות. נבדקו צילומי טפסים בהירים/כהים ומובייל; נדרש עדיין audit מלא לתוכן/מדיה ול־header/footer אמיתיים.

### 14–16: עבודה יומיומית ואוטומציה

[מדריך הבדיקות בעברית](../testing.md) מסביר התקנה, כל פקודה, UI, דוח, trace, הרצה אחת וכישלון בהקמה לעומת כישלון באתר. הוא כולל בדיקות ידניות שנותרו והסבר על מגבלת WebKit. check, unit, UI, report, e2e ו־release הופעלו; release המלא חשף חסימת מערכת ולא דווח כירוק.

Husky פעיל ב־pre-commit. הוא בודק תוכן index, אינו מתקן קבצים ואינו מבצע stash. בדיקות בתיקיית Git זמנית בדקו רווחים בשם וקובץ שהוכנס חלקית, קישור שבור ויעד שטרם נכנס ל־index. התקנת hooks מדולגת ב־production וב־CI.

[תצורת CI](../../.github/workflows/quality.yml) מכילה Checks, Dependency audit ו־Browser tests, הרשאות קריאה בלבד, Bun מקובע, התקנה frozen, artifacts וניסיון חוזר שאינו מסתיר flaky. היא רצה בדחיפה ל־main, ב־PR ובהפעלה ידנית. ה־Actions קובעו ל־commits רשמיים שאומתו. **אין עדיין ריצת GitHub מאומתת.** ההפעלה והדוחות מתוארים ב[מדריך הבדיקות](../testing.md); הגנת ענף היא בחירה ולא תנאי להשלמת העבודה.
